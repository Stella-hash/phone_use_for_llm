# Security reporting

Maintainer: [Stella-hash](https://github.com/Stella-hash). This is a private release
candidate; no production-safe release or response-time guarantee is claimed.

Before a public announcement, the maintainer must enable and verify GitHub private
vulnerability reporting. The intended public channel is **Report a vulnerability**
on the repository's [Security Advisories page](https://github.com/Stella-hash/phone_use_for_llm/security/advisories).
This channel is not yet enabled on the private candidate. While review is private,
use the already established private maintainer review channel. If you have no such
channel and the button is unavailable, do not post security details to an issue;
ask the maintainer to provide a private reporting route without including details.

Reports should contain the affected commit, expected/observed boundary, platform
and a minimal synthetic test description. Exclude credentials, device screenshots,
private logs, household addresses, real targets and exploit chains. Test only
disposable synthetic fixtures or separately authorized isolated environments.

Only the current candidate branch receives fixes during review. Disclosure and
public release wait for the maintainer and independent reviewer to assess the
exact repaired commit. The [deployment boundary](SAFETY.md) applies in every profile.
