# 0.12 source update: review boundary

This change prepares passive latency profiles and optional short delegation on
top of `41651b77369033958d551a73d43f571fcd92cfb8`. It is a review candidate, not
approval to deploy a continuously operating agent. Merge requires independent
review and the exact candidate's Linux, macOS, Windows, source-secret-scan and
CodeQL checks. CodeQL's aggregate check must succeed as well as its analysis
workflow; successful scanning alone is not a passing findings gate. The PR
supplies the current commit and check results.

The update keeps the existing authenticated public Executor, focused-window
owner resolver, key restrictions, URL checks and replay ledger. Household-only
deployment files, credentials, device history, model-run artifacts, continuous
touch and timed-pause features are outside this change.

Review entry points:

- `src/latency.ts` and `src/observation.ts`: passive measurements, condition
  labels, failed samples, source expiry and optional-cache failure isolation.
- `src/delegation-tools.ts`, `src/security.ts` and `src/executor.ts`: distinct
  host lifecycle schemas, explicit consent, normal input authorization and
  queue admission. There is no externally accessible worker bypass token.
- `src/delegation.ts`: single worker ownership, version changes before queued
  input, stop while input/model work is in flight, exact receipt binding,
  cumulative budgets, restart interruption and bounded private metadata.
- `src/delegation-model.ts`, `src/delegation-evidence.ts` and
  `src/delegation-navigation.ts`: fixed endpoint/credential source, bounded
  structured output, copied text versus visual interpretation, source expiry,
  supported navigation and explicit refusal.
- `src/ui.ts` and `android-helper/src/dev/gc/agentphone/helper/UiSnapshotInstrumentation.java`:
  optional active-root collection, real focused-owner checks, bounded complete
  trees, no input, no hidden fallback, and unchanged release-signing rules.

The synthetic suite exercises an allowed swipe through the actual Executor,
Chrome reading through the authenticated HTTP service and model-protocol sink,
denials, takeover, obsolete decisions, request binding, source expiry, restart,
and default-off configuration. No test needs a private endpoint, API credential,
real phone, NAS, or preexisting activity database. `verify:clean` generates an
owner configuration and checks that the ordinary service works without optional
model setup. Helper packaging tests use synthetic compiler/signing sinks;
they do not establish actual SDK compilation, installation or device acceptance.

The public runtime is TypeScript compiled into `dist`; the worker has no import
from an experiment directory or optional action-card service. No dependency was
added. The existing XML parser is upgraded to 5.12.0 and the lockfile updated for
[GHSA-474x-hrwr-fgx4](https://github.com/advisories/GHSA-474x-hrwr-fgx4), discovered
by the production audit. GitHub source is the
distribution; `private: true` remains set and no APK or npm release is included.

The most useful independent check is the legitimate granted path alongside
the version/stop/receipt boundaries: disabling or stalling an auxiliary model
must not silently grant input, claim stale evidence is current, retry an unknown
action, or claim that the host's elapsed time measures physical success.

Follow-up review covers WebView-to-native/group drift for both tap and targeted
scroll, native search identifiers reaching the execution-time helper check,
mutation annotations, and process-only latency notice cursors. Regressions pair
refusals with legitimate paths through the public HTTP/Executor code. Synthetic
helper responses test request binding and non-replay; they do not establish
physical Android focus behavior.

CodeQL alerts 1 and 2 (`js/insufficient-password-hash`) were reviewed at the
previous candidate `c76bb8f9d95d0eb595f4385c3b1a961829a25137`. Their reported source
is the throwing `reject("DELEGATION_PASSWORD_BOUNDARY")` call, not a returned
password. `ActivityJournal.requestDigest` indexes caller request IDs for replay
protection; `actionBinding` compares normalized requests. Neither digest stores
or verifies an authentication password. These are false positives for the
[password-storage rule](https://codeql.github.com/codeql-query-help/javascript/js-insufficient-password-hash/),
and were individually dismissed with those reasons; no query is excluded. Request
digests remain deterministic and guessable for low-entropy arguments, as
disclosed in [the privacy boundary](../SAFETY.md); this triage does not turn them
into a confidentiality mechanism or change the authentication policy.
