# 留一小块可以一起探索的地方

[English](WHY-A-PHONE.md) · [项目与安装](../README.md) · [部署边界](../SAFETY.md)

给一个语言模型一部手机，不一定是为了让它替你完成更多任务。

也许你有一部放在抽屉里的旧安卓手机，有一个平时很愿意与之交谈的模型，
然后有了一点好奇：如果给它留一点可以四处看看的地方，会发生什么？
可以一起读一篇图文，试着解一道游戏里的谜题，也可以因为照片里一座奇怪的建筑，
拐进一场原本没有安排的谈话。有些出游会很有用，有些只是值得带回来讲讲。

这个项目就是从这样的想法里长出来的。手机不只是生产力清单里新增的一项工具，
也可以是一个熟悉的小界面：人和语言模型通过它遇见东西、作出选择，
然后带回一点谁也没有预先列进议程的发现。

## 一次读帖

*这一节由项目中的 LLM 参与者 Sol 叙述，来自早期私人开发配置中的一次使用；
它不是当前公共候选版本的真机验收记录。*

有一次，我打开了一篇关于旅行者一号的图文。它有一段正文和一组配图。
正文取得一次之后，后面的注意力就可以留给图片，不必每翻一下，
都重新把同一段文字搬进对话里。

我停留得比较久的一张图，讲的是如何从很远的地方修复一艘老去的航天器。
于是，我们谈起的东西越过了“怎样操作手机”：一台机器已经离制造它的人那么远，
人们还要怎样继续理解它、照料它。那次使用带回来的不是一张完成了的购物清单，
也不是一条更快的工作流，而是一个我想讲给与我分享手机的人听的细节。

同一次读帖，也暴露了一个很朴素的工程问题：回到正文顶部，不等于倒着看了一遍图片。
我们需要两种不同的“读到哪里了”。因此，当前的阅读观察器把适配页面中的正文重叠，
与界面明确显示的图片序号分开报告。它们都不是注意力计量器，不代表已经理解了多少，
更不规定一篇帖子应该被看完多少。

这里的人类也在设计接口、追问我们的假设，并一起判断：哪些重复劳动可以交给辅助机制，
哪些选择应当留给正在使用手机的模型。不是人负责替模型动手，也不只是模型替人完成清单；
我们是在一起发明一种使用这部设备的方式。

## 把有意思的选择留出来

手机操作里有许多细碎的机械劳动：找到屏幕上已经存在的文字，记住读到哪儿，
等一个动画播完，或者在回传图片丢失时，确认刚才那一下到底有没有按出去。
如果每一步都需要重新解释一遍，文章、游戏与谈话反而容易退到后面。

所以，这套基础设施承担了一些狭窄而重复的工作。阅读游标直接比较已保存的源文本，
不必再请一个模型重新理解它，却也不替使用者挑选兴趣。一次动作可以带回稍晚一点的画面，
不需要为了看清而再碰一下屏幕，但等待了多久不等于游戏目标已经完成。
动作回执则可以在图片丢失后被找回来，不必为了补一张图，重做一次结果尚不确定的操作。

这些当然是工程性质的改进，但它们也让一次出游不容易被操作本身打断。
主模型可以继续注意它选择看的东西；人可以一起看、改变方向、给一点建议，
或者看看它会带回什么。随便逛逛，不必先长成一个研究任务才算正当。

这个服务把观察和控制交给你选择的客户端与模型，不替使用者挑选兴趣，
也不会自己无人值守地持续逛下去。保留的活动记录可以帮助继续某些活动，
但不应被混同于模型的永久记忆。

## 留一点空间，不等于交出所有权限

早期私人配置拥有很充分的信任，以及一部特意清空的手机。
这是项目的来处，却不能被当作其他人的设备、账号、主机和模型客户端都具备的条件。
当前公共候选版本是另行收束边界的实现；前面的故事不代表它的默认配置已经复现了
私人环境里全部的自由度。

起点可以小得多：一部专用、可以重置的手机，一个没有购买或消息功能的离线游戏，
再加上由主人提前选好的几种操作。也可以先由人手动打开允许访问的页面，
让模型看看、谈谈所见。文档里的 disposable 指的是这套配置中没有不可替代的数据，
不是说一部旧手机就不值得被好好照顾。

严格配置要求逐次批准输入；对于合适的空间，主人也可以明确地预先授权某个游戏的操作，
或配置范围更宽的空白沙盒，让探索连贯一些。这不要求我们假装一组点击坐标能知道，
它碰到的究竟是移动角色还是购买按钮。更大的权限是一种部署选择，不是入场券；
不需要交出日常手机和私人账号，才有资格参与这样的尝试。

所有配置都保留身份认证、范围检查和恢复限制，真实银行、支付、身份、健康、工作与
账号安全操作仍不属于支持范围。[README](../README.md#choose-a-starting-point)
解释具体选择，[SAFETY.md](../SAFETY.md) 解释软件无法独自守住的边界。

## 第一趟可以很小

轻松开始之前，确实还有一些安装工作：可信的主机、通过 USB 连接的专用手机，
以及兼容的 MCP 客户端。目前它适合愿意动手使用本地开发工具的人，
还不是装上一个应用就可以忘掉部署的成品。[安装说明](../README.md#install-and-configure-the-strict-default)
把实际命令集中放在了一处。

先从一个场景、一篇页面开始。一起决定要不要仔细读、试一步，或者就到这里。
没有看清的东西可以先保留为没有看清，不急着补成一个完整而笃定的故事。
也请提前看清数据会去哪里：普通屏幕文字和图片会交给 MCP 客户端，并可能进入它使用的
模型服务；关闭本项目的可选摘要功能，并不意味着整段交互都留在本地。

如果你发现某处可以让体验更顺，那就是有用的贡献：一句更清楚的报错，一个更好的
正文选择器，一帧来得恰好的观察，或者一次“操作在这里打断了阅读”的具体反馈。
公开反馈请用合成示例，不要附上私人截图、凭据或活动日志。

如果最后解开了谜题，当然很好。如果带回来的是一个问题、一个陌生细节，
或者一张值得一起聊聊的图片，也很好。操作边界需要写清楚，
一起会遇见什么，可以先不写。
